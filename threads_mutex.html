Module 2 : Threads & Mutex

Ce module traite de la concurrence intra-processus et des mécanismes de synchronisation.

1. Concept de Thread

Un thread est une unité d'exécution au sein d'un processus. Contrairement aux processus, les threads partagent le même espace mémoire (code, données), mais possèdent leur propre pile et registres.

  • Avantage : Communication rapide entre unités de calcul.
  • Risque : Race conditions (accès concurrents non protégés).

2. Atomicité et Data Races

Une opération est atomique si elle s'exécute sans être interrompue par un autre thread. En C++, les types `std::atomic` garantissent que des opérations comme l'incrémentation ne sont pas "coupées" au milieu.

Danger : Une opération non atomique (ex: x = x + 1) peut être décomposée en plusieurs instructions machine, permettant à un autre thread d'intervenir entre le chargement et l'écriture.

3. Mutex et Section Critique

Un Mutex (Mutual Exclusion) est un verrou qui garantit qu'un seul thread accède à une section de code ou à une donnée à la fois.

  • std::mutex : Le type de base.
  • std::unique_lock : Gestion RAII du mutex (déverrouillage automatique).
  • Condition Variable : Permet à un thread d'attendre qu'une condition soit remplie tout en libérant le mutex pendant l'attente.
// Exemple de protection avec unique_lock
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx;
int counter = 0;

void increment() {
    for(int i=0; i<1000; ++i) {
        std::unique_lock<std::mutex> lock(mtx);
        counter++; // Section critique protégée
    }
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);
    t1.join();
    t2.join();
    std::cout << "Final count: " << counter << std::endl;
    return 0;
}

Entraînement C++ : Condition Variables

Implémentez un producteur/consommateur simple utilisant une condition variable pour signaler que la file n'est plus vide.

#include <iostream>
#include <thread>
#include <mutex>
#include <condition_variable>

std::mutex mtx;
std::condition_variable cv;
bool ready = false;

void worker() {
    std::unique_lock<std::mutex> lock(mtx);
    // --- À COMPLÉTER : Utiliser cv.wait avec un prédicat ---
    cv.wait(lock, []{ return ready; });
    std::cout << "Le travail est prêt !" << std::endl;
}

int main() {
    std::thread t1(worker);
    std::this_thread::sleep_for(std::chrono::seconds(1));
    {
        std::lock_guard<std::mutex> lock(mtx);
        ready = true;
    }
    cv.notify_one();
    t1.join();
    return 0;
}

QCM de Validation

1. Pourquoi utiliser std::unique_lock plutôt que mtx.lock() / mtx.unlock() ?

Pour la performance brute.
Pour le principe RAII (déverrouillage automatique en cas d'exception).
Parce que mtx.lock() n'est pas disponible en C++11.

2. Que se passe-t-il si un thread appelle wait() sur une condition variable sans détenir le mutex ?

Le programme plante immédiatement.
Le comportement est indéfini (Undefined Behavior).
Le mutex est automatiquement acquis par le système.
