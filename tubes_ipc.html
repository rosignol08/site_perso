Module 4 : Tubes & IPC

Communication entre processus via les files de données (Pipes).

1. Les Tubes Anonymes (pipe)

Un tube est un canal de communication unidirectionnel. Il possède une capacité limitée et fonctionne sur le principe FIFO.

  • Caractéristiques : Pas de nom dans le système de fichiers, utilisé par des processus liés (parent/fils).
  • Comportement : Lecture bloquante si vide, écriture bloquante si plein.

2. Les Tubes Nommés (mkfifo)

Contrairement aux tubes anonymes, les tubes nommés apparaissent dans le système de fichiers.

  • Accès : Utilisables par n'importe quel processus possédant les droits d'accès.
  • Utilisation : Création avec mkfifo(), ouverture avec open().
Note Technique : L'option O_NONBLOCK permet de rendre les lectures et écritures non bloquantes, utile pour des systèmes réactifs.

3. Exemple d'implémentation

#include <fcntl.h>
#include <sys/types.h>
#include <unistd.h>

int main() {
    int pipefd[2]; // 0 pour lecture, 1 pour écriture
    pipe(pipefd);
    
    // Processus fils
    if (fork() == 0) {
        close(pipefd[1]); // Ferme l'écriture
        char buffer[100];
        read(pipefd[0], buffer, 100);
        printf("Reçu : %s\n", buffer);
    } else {
        close(pipefd[0]); // Ferme la lecture
        write(pipefd[1], "Bonjour du tube !", 16);
    }
    return 0;
}

QCM de Validation

1. Quel est l'avantage principal d'un tube nommé par rapport à un tube anonyme ?

Il permet la communication entre processus sans lien de parenté.
Il est plus rapide car il n'est pas stocké sur le disque.
Il permet une communication bidirectionnelle native.
