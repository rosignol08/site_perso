Module 3 : Sémaphores

Les sémaphores sont des primitives de synchronisation basées sur un compteur.

1. Théorie des Sémaphores

Un sémaphore est une variable entière protégée qui contrôle l'accès à une ressource limitée. Contrairement au mutex (qui est binaire), le sémaphore peut avoir une valeur supérieure à 1.

  • Opération P (proberen / wait) : Décrémente le compteur. Si le compteur est à 0, le processus est mis en sommeil jusqu'à ce qu'un autre fasse un V.
  • Opération V (verhogen / post) : Incrémente le compteur et réveille un processus en attente.

2. Sémaphores POSIX

Il existe deux types de sémaphores dans l'écosystème POSIX :

  • Sémaphores Nommés (System V ou POSIX) : Accessibles par des processus sans lien de parenté via un nom (ex: /my_sem).
  • Sémaphores Anonymes : Utilisés uniquement entre processus liés (souvent via mémoire partagée).
Différence Mutex vs Sémaphore : Un mutex est un verrou d'exclusion mutuelle (propriétaire unique), tandis qu'un sémaphore est une variable de signalisation.

3. Implémentation POSIX

#include <semaphore.h>
#include <stdio.h>

// Initialisation d'un sémaphore nommé
sem_t *sem = sem_open("/new_sem", O_CREAT | O_RDWR, 0666, 1);

// Utilisation
sem_wait(sem); // Opération P
// ... section critique ...
sem_post(sem); // Opération V

sem_close(sem);
sem_unlink("/new_sem");

Entraînement : Gestion de Ressources Limitées

Utilisez un sémaphore pour limiter l'accès à une ressource qui ne peut accepter que 3 utilisateurs simultanément.

#include <semaphore.h>
#include <stdio.h>
#include <unistd.h>

sem_t *sem_limit;

void* worker(void* id) {
    printf("Processus %ld attend le sémaphore...\n", (long)id);
    sem_wait(sem_limit);
    printf("Processus %ld entre dans la zone.\n", (long)id);
    sleep(2);
    sem_post(sem_limit);
    printf("Processus %ld libère le sémaphore.\n", (long)id);
    return NULL;
}

int main() {
    // Initialiser à 3 pour permettre 3 accès simultanés
    sem_init(&sem_limit, 1, 3); // Note: ici sem_init pour un sémaphore anonyme
    // Pour un nommé, utilisez sem_open.
    
    // ... code de création des threads ...
}
